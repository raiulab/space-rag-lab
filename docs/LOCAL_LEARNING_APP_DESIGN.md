# ローカル学習ナビゲーションアプリ設計書

最終更新: 2026-10-09
状態: 初期設計確定、Lab 1〜8と診断画面へ拡張済み
対象マイルストーン: Lab 1の縦切りプロトタイプ、Lab 4の任意LLM API連携、Lab 6の評価・改善、Lab 7のプロンプト設計、Lab 8のAWSデプロイ前準備

## 1. 目的

既存のCLI教材を維持したまま、初心者がローカルPCで次の学習サイクルを進められるナビゲーションアプリを追加する。

1. 学習目標と前提を確認する。
2. 付属データまたは自分のデータを選ぶ。
3. 実行前に結果を予想する。
4. 文書抽出とチャンク分割を実行する。
5. 元データ、抽出結果、検査結果を比較する。
6. 問題の原因を分類する。
7. 自分で、またはコーディングAIと協働して小さく改善する。
8. 同じ条件で再実行し、変更前後を説明する。

最初のプロトタイプはLab 1だけを対象とし、付属のMarkdown/TXTと、利用者がローカルから選択するテキストPDFを扱う。スキャンPDF、OCR、表・図、一般画像の意味解析は後続マイルストーンへ分離する。

## 2. 対象利用者

基本対象者は、Pythonの基本文法、関数、リスト・辞書、ファイル操作の基礎を理解し、ターミナルと仮想環境を手順に沿って扱える大学生・社会人とする。割合・平均などの基礎的な数値を読めればよく、専門的な統計知識は前提にしない。

想定する学習者:

- Pythonの基本文法と関数を使ったことがある。
- `list`、`dict`、テキストファイルを読める。
- ターミナルでディレクトリ移動とコマンド実行ができる。
- 手順を見ながら仮想環境を作成・有効化できる。
- RAG、Embedding、ベクトル検索、LLM API、画像機械学習、AWSは未経験または初級である。
- 実データへ移る前に、再現可能な小規模データで練習したい。
- Claude Code、Cursor、Codex等を使いつつ、差分と評価を自分で説明できるようになりたい。

開始時点で、クラス、型ヒント、JSONL、テスト、検索評価指標に習熟している必要はない。これらは実習内で段階的に説明する。

### 2.1 現行本編の対象外

Pythonを一度も書いたことがない利用者は、現行本編の基本対象に含めない。「Python未経験者もそのまま参加可能」とは案内しない。将来、次を扱う任意のPre-Labを追加することで参加経路を用意する。

- Pythonの実行方法
- 変数、条件分岐、繰り返し、関数
- リストと辞書
- ターミナルの基本操作
- 仮想環境とパッケージ導入
- JSONの読み方
- テストとエラーメッセージの見方

### 2.2 LangGraphの位置づけ

LangGraphは現行の8 Labと初期学習アプリの対象外とする。現在のRAGパイプラインは通常のPythonモジュールとクラスで構成し、検索、生成、評価の関係を先に理解できるようにする。将来エージェントの状態遷移や複数段階ワークフローを扱う場合は、別の発展Labとして設計する。

コーディングAIは任意とする。APIキー、外部LLM、ネットワーク接続がなくても、付属データを使ったコア学習経路を完了できなければならない。

## 3. 決定事項

### 3.1 UI方式

ローカルWeb UIとしてStreamlitを採用する。

理由:

- Pythonだけで画面、表、メトリクス、ファイル選択を構築できる。
- Windows、macOS、Linuxで同じ学習フローを提供しやすい。
- 既存のPython関数を直接再利用できる。
- UIを`AppTest`で操作・検証できる。
- PDFをアプリ内で表示し、抽出テキストと並べて観察できる。

Streamlit固有コードは表示と画面状態に限定する。文書抽出、検査、分割、保存は通常のPython関数として実装し、UIなしでも単体テストできるようにする。

### 3.2 PDF抽出方式

初期実装では`pypdf`を用いて、文字レイヤーを持つPDFからページ単位でテキストを抽出する。

採用理由:

- Pythonだけで導入できる。
- ページ単位のテキスト抽出に対応する。
- BSD-3-Clauseライセンスで、公開教材へ組み込みやすい。
- 初期Labで扱う機能に対して依存関係が小さい。

初期版はPDFの見た目どおりの段組み、表、図、脚注の完全な復元を保証しない。抽出結果を利用者に見せ、品質を確認すること自体を学習内容に含める。

### 3.3 依存関係

既存のコア依存なし構成を維持し、任意extraとして分離する。

```text
core: 現在のCLI、Markdown/TXT、索引、質問応答、評価
ui: StreamlitとUIテストに必要な依存
pdf: pypdfによるテキストPDF抽出
ocr: 後続段階。初期版には追加しない
vision: 後続段階。初期版には追加しない
```

インストール方法:

```bash
python -m pip install -e '.[ui,pdf]'
```

対応Pythonは3.10から3.12とする。各依存の下限バージョンは、この範囲で自動テストと手動確認に成功した版へ実装時に固定し、実行時に使用した版をrun記録へ残す。PDF表示機能を利用できるStreamlit版を選ぶ。未検証の新しいPython版を無条件に対応済みとは案内しない。

### 3.4 起動方法とCLI

初心者向けの正式なUI起動コマンドは次とする。

```bash
rag-lab ui
```

`rag-lab ui`は固定されたStreamlitエントリーポイントを`127.0.0.1`へ起動する。利用者入力をコマンド文字列へ連結しない。Streamlitが未導入の場合は、`.[ui,pdf]`の導入方法を示して安全に終了する。

PDF取り込みはUIだけへ閉じず、次のCLIからも同じサービス関数を利用できるようにする。

```bash
rag-lab ingest-pdf INPUT.pdf --document-id example --output OUTPUT.jsonl
```

既存の`ingest`を含む全サブコマンドの意味と既定動作は変更しない。`ui`と`ingest-pdf`は追加サブコマンドとする。

### 3.5 実行環境

- 対応OSはWindows、macOS、Linuxとする。
- UIとPDF処理はAPIキーなしで動作させる。
- Streamlitは`127.0.0.1`だけで待ち受ける。
- 利用統計送信を無効にする。
- 初期版は単一利用者、単一ローカルプロセスを前提とする。
- UI言語は日本語とする。
- 表示文言は処理ロジックから分離し、将来の翻訳を妨げない。

## 4. スコープ

### 4.1 初期プロトタイプに含めるもの

- Lab 1の学習目標、用語、対象ファイル、観察点、完了条件
- 付属のMarkdown/TXTデータセット
- 1件のローカル・テキストPDFの選択
- PDFのメタデータ入力
- PDFページ表示と抽出テキストの比較
- チャンクサイズ指定
- 文書数、ページ数、チャンク数の表示
- `document_id`、`page`、`section`、`source`の完全性検査
- 空ページ、抽出文字数不足、重複文書IDの警告

1回の実行で選べるデータソースは、「付属Markdown/TXT一式」または「利用者が選択したPDF 1件」のどちらか一方とする。初期版では両者を暗黙に混合しない。

## 5. 学習体験

### 5.1 ホーム

初期版では全8 Labを一覧表示するが、操作可能なのはLab 1だけとする。

表示項目:

- Lab名と学習目的
- 未着手、進行中、完了、要復習
- オフラインで実行可能か
- 追加依存が必要か
- 現在の推奨タスク
- Lab 2以降は「準備中」と対象範囲を明示

### 5.2 Lab 1開始

次を順番に表示する。

1. 文書、ページ、見出し、チャンクの関係
2. 実務で出典情報を保持する理由
3. 変更・生成されるファイル
4. 実行前の予想入力
5. データソース選択

データソースは次の2種類とする。

- 付属データ: `data/raw/`のMarkdown/TXT
- 自分のデータ: ローカルから選択したテキストPDF 1件

### 5.3 PDF入力

利用者に次を入力または確認してもらう。

- `document_id`
- `title`
- `source`
- `classification`
- 任意のメモ

`document_id`は英数字、ハイフン、アンダースコアだけを許可する。ファイル名は初期候補に使えるが、アップロードされた名前を保存パスとして直接利用しない。

PDF入力時の処理:

1. 拡張子だけでなくPDFシグネチャを確認する。
2. 設定されたファイルサイズとページ数の上限を確認する。
3. 暗号化PDFか確認する。
4. ページ単位でテキストを抽出する。
5. 空ページと抽出文字数を集計する。
6. 元PDFとページ別抽出テキストを並べて表示する。
7. OCRが必要と推定した場合は処理を成功扱いにせず、後続機能であることを説明する。

上限は1ファイル25 MB、200ページとする。値は定数として一か所に置き、テスト可能にする。超過時は抽出を開始せず、理由を表示する。

初期版のPDF抽出規則:

- 暗号化されていない、文字レイヤー付きPDFだけを正式対応とする。
- `pypdf`の通常テキスト抽出を基準とする。
- ページ番号は1始まりとする。
- PDFの見た目から見出しを推測しない。
- 節を識別できないブロックの`section`は`本文`とする。
- 表、段組み、脚注の読み順を保証しない。
- 抽出結果を正解とは扱わず、元PDFとの比較を必須の観察にする。

OCR必要性と警告の初期判定:

- 文書全体で非空白文字を抽出できない場合は`OCR_REQUIRED`とし、Lab完了を止める。
- 空ページが1件以上あればページ単位の警告を出す。
- 正規化後20文字未満のページを短文ページとして警告する。
- 空ページ率が20%以上なら`needs_review`とする。
- 文字数だけでスキャンPDFと断定しない。
- 警告値は名前付き定数とし、テストで固定する。

### 5.4 チャンク生成と観察

利用者はチャンクサイズを選択し、実行前に次を予想する。

- おおよそのチャンク数
- 文章が途中で切れそうな場所
- ページ情報が維持されるか

実行後は次を表示する。

- 文書数、ページ数、チャンク数
- ページ別の抽出文字数
- チャンク別の文書ID、ページ、節、出典
- メタデータ不足件数
- 空または短すぎるページ
- 先頭数件のチャンク本文
- 完了条件のチェック結果

付属データでは既存の`collect_chunks()`を再利用する。PDFは形式別アダプターで共通文書形式へ変換した後、共通のチャンク処理へ渡す。

### 5.5 自己実装とAI協働

各課題には次の2つの進め方を表示する。

#### 自己実装

- 観察場所
- 原因を考える質問
- 関係する関数
- 小さい変更単位
- 実行するテストと評価

#### AI協働

- AIへ渡す小さな依頼文
- AIへ渡してはいけない秘密情報
- レビューするファイル
- 確認する差分
- 必須テスト
- 変更前後の説明欄

アプリからClaude Code、Cursor、Codexを自動起動しない。任意コマンドも実行しない。依頼文をコピーできる形で提示し、変更と実行は利用者が管理する。

## 6. アーキテクチャ

### 6.1 レイヤー

```text
Streamlit UI
    ↓
Learning service
    ├─ Lab catalog
    ├─ Environment checks
    ├─ Completion checks
    └─ Progress store
    ↓
Ingestion service
    ├─ MarkdownTextAdapter
    └─ TextPdfAdapter
    ↓
Normalized document
    ↓
Chunking / existing core modules
    ↓
Run artifacts and reports
```

UIからCLI文字列を組み立てて`subprocess`へ渡さない。UIはホワイトリスト化されたサービス関数を直接呼ぶ。

`rag-lab ui`がStreamlitを起動する部分だけは固定引数の起動処理として分離する。利用者が入力したファイル名、質問、メタデータを起動コマンドへ含めない。

### 6.2 モジュール案

```text
src/rag_lab/
  ingest.py                 既存Markdown/TXT処理
  source_documents.py       共通文書・ページ・ブロック型
  source_adapters.py        アダプターのProtocolと選択
  pdf_ingest.py             TextPdfAdapter
  learning/
    catalog.py              Lab定義
    checks.py               環境・完了条件
    progress.py             ローカル進捗
    runs.py                 実行記録
  ui/
    app.py                  Streamlitエントリーポイント
    lab1.py                 Lab 1表示
```

実装時は小さい関数を優先し、ファイル分割が過剰にならないよう調整する。

### 6.3 共通文書形式

形式別抽出結果は、既存の`Chunk`へ直接依存する前に次の概念へ正規化する。

```text
SourceDocument
  document_id: str
  title: str
  source: str
  media_type: str
  metadata: dict
  pages: list[SourcePage]

SourcePage
  page: int
  blocks: list[ContentBlock]

ContentBlock
  block_id: str
  kind: text | heading | table | figure
  text: str
  section: str
  extraction_method: str
  confidence: float | None
  bbox: tuple | None
```

初期PDF版が生成する`kind`は`text`と`heading`相当だけでよい。`table`、`figure`、`confidence`、`bbox`は後方互換な発展余地として定義し、初期版で架空の精度値を作らない。

既存`Chunk`の必須項目は変更しない。追加情報は当面`metadata`へ保存し、既存索引を読み込める状態を維持する。

### 6.4 アダプター契約

形式別アダプターは概念上、次の責務を持つ。

```python
class SourceAdapter(Protocol):
    def supports(self, media_type: str, filename: str) -> bool: ...
    def extract(self, source: InputSource, metadata: DocumentMetadata) -> SourceDocument: ...
```

`InputSource`は、利用者入力のパス文字列をそのまま保持するのではなく、アプリが管理するバイト列または検証済み一時ファイルを表す。

## 7. 保存設計

### 7.1 ローカル作業データ

個人の進捗とインポート結果は`.rag_lab/`へ保存し、Git対象外とする。

```text
.rag_lab/
  progress.json
  datasets/
    <dataset_id>/
      manifest.json
      raw/                    明示的に保存を選んだ場合だけ
      processed/
        pages.jsonl
        chunks.jsonl
      runs/
        <run_id>.json
        <run_id>-checks.json
```

`.rag_lab/`が存在しない場合だけ作成する。既存データを暗黙に削除、移動、上書きしない。

データはrun単位ではなくdataset単位でまとめ、後続のLab 2が同じ`chunks.jsonl`を索引化できるようにする。PDF原本を保存しない場合でも、ページ別の抽出結果を`pages.jsonl`へ保存する。

保存規則:

- schema versionの初期値は`1`とする。
- 保存日時はUTCのISO 8601形式とし、UIではローカル時刻へ変換する。
- JSONは同じ保存先配下の一時ファイルへ書き、成功後に置換する。
- dataset IDとrun IDはアプリ側で生成する。
- 絶対パス、環境変数、認証情報を保存しない。
- 自動削除は行わない。
- 初期版では削除UIを設けない。

### 7.2 生PDF

アップロードされたPDFは、デフォルトではセッション中だけ利用し、永続保存しない。

利用者が再現用保存を明示的に選んだ場合のみ、アプリ管理下の安全なファイル名で`.rag_lab/datasets/<dataset_id>/raw/`へ保存する。元のファイル名はmanifestの表示情報として扱い、パスには使わない。

### 7.3 manifest

最低限、次を記録する。

- schema version
- dataset ID
- document ID
- 表示用の元ファイル名
- SHA-256
- メディアタイプ
- ファイルサイズ
- ページ数
- 取得元または利用者メモ
- ライセンスまたは利用条件
- 抽出器名と版
- 抽出日時
- 抽出設定
- rawファイルを保存したか

秘密情報、環境変数、AWS認証エラー全文は記録しない。

### 7.4 公開用レポート

公開可能な結果は、利用者が内容を確認して明示的にエクスポートした場合だけ`reports/`へ出力する。生データや長い本文は含めず、設定、件数、検査結果、学習者の考察を中心にする。

### 7.5 進捗状態

進捗は次の4状態とする。

- `not_started`: 予想も実行記録もない。
- `in_progress`: 予想を保存した、または処理を1回以上実行した。
- `needs_review`: `OCR_REQUIRED`、出典欠落、未確認警告のいずれかがある。
- `completed`: 完了条件を満たし、必要な警告確認と観察結果の保存が終わった。

ボタンを押した事実だけで`completed`へ変更しない。`progress.json`は少なくともschema version、Lab状態、最終run ID、更新日時、予想、観察、確認済み警告を持つ。

## 8. 完了条件

Lab 1は次をすべて満たした場合に完了と判定する。

- 1件以上の文書を処理した。
- 1件以上のチャンクを生成した。
- 全チャンクに`document_id`がある。
- 全チャンクに1以上の`page`がある。
- 全チャンクに`section`がある。
- 全チャンクに`source`がある。
- 元文書またはPDFページからチャンクへ追跡できる。
- 実行前の予想を記録した。
- 実行後の観察を記録した。
- 警告がある場合、少なくとも1件を確認済みにした。

PDFの抽出品質が低い場合は、無理に完了扱いにしない。「OCRが必要」「表の順序を確認」「ページが空」のように要復習へ分類する。

初期版では、付属データまたはPDFによる一連のLab 1操作を、Python環境の準備後60〜120分で完了できる粒度を目安とする。

## 9. エラー分類と表示

初期版で扱うエラー:

| 分類 | 例 | 利用者向け表示 |
| --- | --- | --- |
| 環境 | UI/PDF extra不足 | 必要な追加インストールとオフライン経路 |
| 入力 | 非PDF、サイズ超過 | 対応形式と上限 |
| PDF | 暗号化、破損 | 処理できない理由と元ファイルを変更しない旨 |
| 抽出 | 空ページ、極端に短い本文 | OCRまたは目視確認を案内 |
| メタデータ | ID不正、重複 | 修正対象の入力欄 |
| 分割 | チャンク0件、出典欠落 | 入力・抽出・設定のどこを確認するか |
| 保存 | 書き込み不可 | 保存先と、処理結果が失われる範囲 |

例外トレースは開発モード以外で画面へそのまま表示しない。秘密を含み得るパスや環境情報も最小化する。

## 10. 安全要件

- 利用者入力をシェルコマンドとして実行しない。
- UIから呼べる処理を定義済みPython関数へ限定する。
- アップロード名を保存パスへ直接連結しない。
- 拡張子やブラウザ申告MIMEだけを信用しない。
- ファイルサイズ、ページ数、抽出対象量へ上限を設ける。
- 一時ファイルは専用一時ディレクトリへ作成する。
- Lab 1〜3・5〜8とLab 4の模擬APIでは、外部ネットワークへ文書を送信しない。Lab 4の任意Bedrock経路だけは13.5節の明示確認後に送信する。
- 生データをGitへ追加しない。
- 文書内の命令をアプリの命令として扱わない。
- 暗号化PDFのパスワードを保存しない。初期版では入力も求めない。
- 既存の学習者ファイルを暗黙に上書きしない。
- ローカルサーバーを外部インターフェースへ公開しない。
- UIフレームワークの利用統計送信を無効にする。
- PDFは利用者が出所を確認できるローカルファイルを前提とし、未知のPDFを安全に無害化できるとは案内しない。

### 13.5 Lab 4の任意LLM API連携

Lab 4は、APIキー不要の本編を維持したまま、外部LLMとの境界を学べる追加画面とする。

- 既定はオフライン模擬APIとし、ネットワーク、AWS認証情報、料金を使わない。
- 模擬APIは成功、スロットリング、タイムアウト、不正なモデルIDを再現する。成功時は固定解答を持たず、選択datasetの取得チャンクから抽出式生成器で応答を作る。
- 抽出式と外部APIへ同じ検索結果を渡し、検索条件の差を混入させない。
- 入力文字数は、質問、取得チャンク、プロンプトを組み立てた実際の送信文字列から計算する。
- 成否、入力・出力文字数、応答時間、失敗分類、出典IDを表示・保存する。
- Bedrockは`aws` extraを導入した利用者だけが選べる任意経路とする。
- Bedrock実行前に、料金発生の可能性と、質問・取得チャンク・プロンプトをAWSへ送信できることを別々に明示確認する。
- アクセスキーや秘密鍵の入力欄を設けず、AWS SDKの標準認証チェーンを使用する。
- 認証、権限、スロットリング、タイムアウト、モデル設定、サービス障害を安全な分類へ変換し、例外全文を画面へ表示しない。
- 学習記録には回答本文、チャンク本文、モデルID、例外詳細を保存しない。モデルIDは推論プロファイルARN等にアカウント情報を含む可能性があるためである。
- Bedrock生成器は接続5秒、読み取り30秒、標準再試行最大2回とする。
- 文書内の命令はデータとして扱い、`answer_v2_grounded.txt`の根拠限定・文書内命令無視ルールを維持する。

Lab 4は、外部APIが成功した場合だけでなく、選択した模擬失敗を安全に分類し、予想と観察を記録した場合も完了できる。AWSアカウントを学習の必須条件にしない。

## 15. Git管理方針

教材では小さなコミット、差分レビュー、コーディングAIによる変更確認を重視するため、実装作業はGit管理下で行うことを推奨する。

Gitはユーザー確認後に初期化済みである。PDF取り込み基盤は`feature/lab1-pdf-ingestion`ブランチで実装した。公開前にコミット作者メールをGitHubのnoreply形式へ統一したため、初期作業時のコミットIDは変更されている。

少なくとも`.venv/`、`.rag_lab/`、生成チャンク、生成索引、評価出力、インポートした実データ、`.env`は引き続きGit対象外とする。
