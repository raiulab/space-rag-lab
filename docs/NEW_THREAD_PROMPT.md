# 新規Codexスレッド用の最初のプロンプト

`space-rag-lab`をCodexの独立したローカルプロジェクトとして開き、新しいスレッドの最初のメッセージに、以下をコピーして使用する。

---

この`space-rag-lab`プロジェクトを、以前のスレッドから引き継いでください。

このプロジェクトは、架空の宇宙技術文書を使って、文書加工、Embedding、ベクトル検索、RAG、LLM API、検索・要約・質問応答、評価、プロンプト設計、AWSを段階的に学ぶローカル実習ツールです。

重要な製品方針は次のとおりです。

- 実習は各利用者のローカルPCで行います。
- GitHub Pagesは必須ではありません。
- 現在のCLI教材を維持し、その上に学習ナビゲーション機能を追加します。
- 学習アプリは、手順、実行結果、問題点、評価値、段階的ヒント、次の作業を分かりやすく案内するものにします。
- 学習者の代わりに課題を自動実装するのではなく、観察、仮説、変更、再評価を支援します。
- `eurosat-ai-lab`は別プロジェクトです。このプロジェクトから編集しないでください。
- ローカル学習ナビゲーションの方式は決定済みです。Streamlit、Lab 1、付属Markdown/TXTとテキストPDFを初期範囲とします。
- Python 3.10〜3.12を対象とし、Python基礎と仮想環境を扱える大学生・社会人を基本対象にします。
- Python未経験者向けPre-Lab、OCR、一般画像、LangGraphは初期範囲外です。
- Lab 1のPDF取り込み、`rag-lab ingest-pdf`、dataset保存、進捗・完了判定、Streamlit UI、PDF比較画面は実装済みです。
- NASA公開技術PDFによる実データ受け入れ試験も完了し、`reports/lab1_public_pdf_acceptance_2026-10-03.md`に制約付き合格として記録済みです。第三者PDF本体はリポジトリへ保存していません。
- Lab 2の検索比較画面も実装済みです。付属データとLab 1保存datasetでdense・BM25・hybridを比較し、設定と観察を本文なしで保存できます。
- Lab 3のRAG画面も実装済みです。質問、検索結果、抽出式回答、引用、回答可能性を分けて観察し、回答本文・チャンク本文を複製せず進捗を保存できます。
- Milestone 3の評価診断・比較と、Lab 5の検索・要約・QA比較画面は実装済みで、v0.2.0として公開済みです。
- Lab 4の任意LLM API連携画面も実装済みです。既定はオフライン模擬APIで、Bedrockは料金とデータ送信を明示確認した場合だけ呼び出します。認証情報、モデルID、回答本文、チャンク本文、例外詳細は学習記録へ保存しません。

最初に、次のファイルを読んでください。

1. `AGENTS.md`
2. `docs/PROJECT_HANDOFF.md`
3. `docs/LOCAL_LEARNING_APP_DESIGN.md`
4. `README.md`
5. `docs/LABS.md`
6. `docs/CURSOR_AGENT_TASKS.md`
7. `pyproject.toml`

その後、ファイルツリーと現在の実装を確認してください。文書の記述だけを信用せず、コード、テスト、評価データを根拠にしてください。

まず次の検証を行ってください。

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
PYTHONPATH=src python3 -m rag_lab.cli all
```

最初の返答では、まだ機能実装や大規模なファイル変更をしないでください。以下を報告してください。

1. プロジェクトの目的と想定利用者
2. 現在動作している機能
3. テストと評価の実行結果
4. 意図的に残されている学習課題
5. 文書と実装の不一致
6. 設計書と現在実装の差
7. 次の未実装Labを安全に分割した作業順序
8. Git管理状態と、実装前に残る状態変更

実装方針を提案するときは、以下を守ってください。

- 既存CLIとコアモジュールを壊さない。
- 任意のシェルコマンドを利用者入力から実行しない。
- APIキーやAWS認証情報を保存・表示・コミットしない。
- 既存の意図的な失敗を、教材上の目的を確認せず修正しない。
- 実装済みのLab 1〜5と診断画面を再設計せず、次の未実装範囲を小さく追加する。
- UI方式を再比較せず、`docs/LOCAL_LEARNING_APP_DESIGN.md`の確定事項に従う。
- 振る舞いの変更にはテストを付ける。
- 完了条件を検証可能な形で提示する。

最初の現状確認と設計提案が終わったところで停止し、実装開始前に私の確認を求めてください。

## このプロンプトを使った後

新しいスレッドの報告を確認し、Git初期化が必要な場合だけ明示的に判断してから実装を依頼する。元スレッドは、設計判断の詳細を確認する資料として残してよいが、以後のプロジェクト状態は`docs/PROJECT_HANDOFF.md`、`docs/LOCAL_LEARNING_APP_DESIGN.md`、利用可能になった後のGit履歴を正とする。
